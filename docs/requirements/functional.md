# Функциональные требования и критерии приёмки

> **План релизов:** MVP‑1 — оплата, активация, анкета, серверный КБЖУ, рацион; остальные функции сохранены для последующих итераций. Новые ФТ не заменяют ФТ‑01…ФТ‑28.

## Дополнительные критерии приёмки ФТ

| ID | ФТ | Проверяемое условие |
|---|---|---|
| <a id="kp-ft-11"></a>КП-ФТ‑11 | ФТ‑11 | При выборе «дом» → «без инвентаря» программа не содержит упражнений, требующих дополнительного оборудования. |
| <a id="kp-ft-21"></a>КП-ФТ‑21 | ФТ‑21 | При переключении между днями недели отображаются соответствующие им приёмы пищи из сформированного плана. |
| <a id="kp-ft-27"></a>КП-ФТ‑27 | ФТ‑27 | В анкете доступны поля цели, стажа тренировок и активности; введённые значения сохраняются для дальнейшего подбора плана. |
| <a id="kp-ft-28"></a>КП-ФТ‑28 | ФТ‑28 | Выбранные физические ограничения сохраняются в данных анкеты и доступны механизму подбора тренировок. |
| <a id="kp-ft-32"></a>КП-ФТ‑32 | ФТ‑32 | Повторная проверка того же invoice_id не создаёт второй платёж или повторное предоставление доступа. |
| <a id="kp-ft-37"></a>КП-ФТ‑37 | ФТ‑37 | Сервер применяет формулу Миффлина — Сан Жеора и согласованные коэффициенты, возвращает BMR, TDEE, target_calories и macros; клиент не рассчитывает эти значения. |
| <a id="kp-ft-38"></a>КП-ФТ‑38 | ФТ‑38 | Промежуточные ответы не отправляются на сервер; единый payload отправляется на финальном шаге в POST /custom/calculate-nutrition. |

## Планирование

- ФТ‑08…ФТ‑12, ФТ‑14…ФТ‑17, ФТ‑20…ФТ‑22, ФТ‑24, ФТ‑26, ФТ‑28: относятся к отложенным возможностям полностью или частично.
- ФТ‑29…ФТ‑38: детализируют архитектурную схему, причём ФТ‑37 и ФТ‑38 уточняют уже существующие БТ.
