# Бизнес-требования и критерии приёмки

> **Версия после сверки архитектурного исследования (05.11.2026).** БТ‑01…БТ‑22 сохранены по ID; новые БТ‑23…БТ‑27 отражают оплату и доступ. 
Статус реализации отделён от существования требования. При разногласиях действует пометка «согласовать», а не автоматическое изменение объёма работ.


| ID БТ | Бизнес-требование | ID КП-БТ | Критерий приёмки |
|---|---|---|---|
| <a id="bt-01"></a>БТ‑01 | Система должна проводить пользователя через многошаговую анкету | <a id="kp-bt-01"></a>КП-БТ‑01 | Пользователь проходит все шаги анкеты, ветвления работают |
| <a id="bt-02"></a>БТ‑02 | Система должна валидировать параметры тела: вес, желаемый вес, рост, возраст | <a id="kp-bt-02"></a>КП-БТ‑02 | Некорректные параметры тела и выбор блокируются |
| <a id="bt-03"></a>БТ‑03 | Система должна учитывать пол и признак грудного вскармливания | <a id="kp-bt-03"></a>КП-БТ‑03 | Пол и грудное вскармливание учитываются в расчетах |
| <a id="bt-04"></a>БТ‑04 | Система должна рассчитывать дневную норму КБЖУ | <a id="kp-bt-04"></a>КП-БТ‑04 | Суточная норма КБЖУ рассчитывается по формуле |
| <a id="bt-05"></a>БТ‑05 | Система должна формировать план питания на 4 недели | <a id="kp-bt-05"></a>КП-БТ‑05 | План питания на 4 недели составляется и отображается в личном кабинете |
| <a id="bt-06"></a>БТ‑06 | Система должна учитывать пищевые ограничения, но не более 5 категорий | <a id="kp-bt-06"></a>КП-БТ‑06 | Нельзя выбрать более 5 пищевых ограничений |
| <a id="bt-07"></a>БТ‑07 | Система должна уточнять исключения по молочным, мясным и рыбным продуктам | <a id="kp-bt-07"></a>КП-БТ‑07 | Исключение подкатегорий продуктов работают |
| <a id="bt-08"></a>БТ‑08 | Система должна формировать программу тренировок с учетом физических ограничений | <a id="kp-bt-08"></a>КП-БТ‑08 | Программа тренировок составляется и отображается в личном кабинете |
| <a id="bt-09"></a>БТ‑09 | Система должна учитывать место занятий | <a id="kp-bt-09"></a>КП-БТ‑09 | Выбор "дом/зал" влияет на составление программы тренировок |
| <a id="bt-10"></a>БТ‑10 | Система должна учитывать инвентарь для занятий дома, если не выбран вариант «без инвентаря»; | <a id="kp-bt-10"></a>КП-БТ‑10 | Для дома учитывается инвентарь (при выборе) |
| <a id="bt-11"></a>БТ‑11 | Система должна позволять выбрать проблемные зоны | <a id="kp-bt-11"></a>КП-БТ‑11 | Проблемные зоны сохраняются |
| <a id="bt-12"></a>БТ‑12 | Система должна предоставлять личный кабинет с данными участника | <a id="kp-bt-12"></a>КП-БТ‑12 | Данные участника отображаются в личном кабинете |
| <a id="bt-13"></a>БТ‑13 | Система должна позволять сохранять вес не чаще 1 раза в день | <a id="kp-bt-13"></a>КП-БТ‑13 | Вес сохраняется раз в день |
| <a id="bt-14"></a>БТ‑14 | Система должна позволять сохранять замеры не чаще 1 раза в день | <a id="kp-bt-14"></a>КП-БТ‑14 | Замеры сохраняются раз в день |
| <a id="bt-15"></a>БТ‑15 | Система должна строить график замеров, если замеров 2 и более | <a id="kp-bt-15"></a>КП-БТ‑15 | График замеров строится от 2 записей |
| <a id="bt-16"></a>БТ‑16 | Система должна предоставить возможность ведения фото-прогресса(опционально) | <a id="kp-bt-16"></a>КП-БТ‑16 | Фото-прогресс доступен, но не обязателен |
| <a id="bt-17"></a>БТ‑17 | Система должна показывать подобранный план питания, продукты, рецепт, правила, корзину на неделю, приемы пищи на неделю, КБЖУ, замену | <a id="kp-bt-17"></a>КП-БТ‑17 | На странице плана питания есть карточки приемов пищи, рекомендации и продуктовая корзина; карточка приема пищи содержит рецепт, ингредиенты, КБЖУ, кнопку замены |
| <a id="bt-18"></a>БТ‑18 | Система должна показывать подобранную программу тренировок на неделю с видео | <a id="kp-bt-18"></a>КП-БТ‑18 | Тренировки отображаются по неделям, видео воспроизводятся |
| <a id="bt-19"></a>БТ‑19 | Система должна предоставлять ссылку на Telegram-чат с инструктором | <a id="kp-bt-19"></a>КП-БТ‑19 | Ссылка на Telegram работает |
| <a id="bt-20"></a>БТ‑20 | Система должна позволять сбросить анкету и пройти ее заново | <a id="kp-bt-20"></a>КП-БТ‑20 | Анкету можно сбросить |
| <a id="bt-21"></a>БТ‑21 | Система должна использовать заранее подготовленную базу приемов пищи, созданную нутрициологом | <a id="kp-bt-21"></a>КП-БТ‑21 | План питания строится только из приемов пищи, добавленных в базу |
| <a id="bt-22"></a>БТ‑22 | Система должна использовать заранее подготовленную базу тренировок, созданную тренером | <a id="kp-bt-22"></a>КП-БТ‑22 | Программа тренировок строится только из видео, добавленных в базу |
| <a id="bt-23"></a>БТ‑23 | Система должна принимать данные покупателя и инициировать оплату марафона через CloudPayments. | <a id="kp-bt-23"></a>КП-БТ‑23 | При корректных ФИО и e-mail создаётся заказ pending_payment с уникальным invoice_id; платежный виджет получает сумму и ID заказа. |
| <a id="bt-24"></a>БТ‑24 | Система должна подтверждать результат оплаты на сервере до выдачи доступа к марафону. | <a id="kp-bt-24"></a>КП-БТ‑24 | После проверки через API CloudPayments оплаченный заказ переходит в paid и фиксирует сведения о транзакции; непроверенная оплата не выдаёт доступ. |
| <a id="bt-25"></a>БТ‑25 | После подтверждённой оплаты менеджер должен иметь возможность пригласить участника для создания учётной записи. | <a id="kp-bt-25"></a>КП-БТ‑25 | Участник получает приглашение Directus и может активировать аккаунт, задав пароль; до активации вход недоступен. |
| <a id="bt-26"></a>БТ‑26 | Участник должен авторизоваться и получать доступ только к собственному кабинету и данным. | <a id="kp-bt-26"></a>КП-БТ‑26 | Активированный Participant входит в кабинет; до активации и без авторизации защищённые страницы и данные недоступны. |
| <a id="bt-27"></a>БТ‑27 | После завершения анкеты система должна сохранять ответы, параметры, рассчитанное КБЖУ и план питания для соответствующего участника. | <a id="kp-bt-27"></a>КП-БТ‑27 | После успешной отправки созданы связанные с user id записи анкеты, профиля, nutrition_calculations и meal_plans; участник видит свой результат. |
