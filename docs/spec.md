### Основные пользовательские сценарии

1. Пользователь проходит многошаговую анкету.
2. Выбирает цель, пол, параметры тела, стаж тренировок, активность, пищевые исключения, физические ограничения, место занятий, проблемные зоны.
3. Получает расчет суточного КБЖУ.
4. Получает план питания на 4 недели.
5. Получает программу тренировок.
6. В личном кабинете сохраняет вес, замеры, фото.
7. При необходимости пишет инструктору в группу в Telegram.

## Требования и ограничения

### Бизнес-требования

| ID    | Бизнес-требование |
|-------|-------------------|
| БТ‑01 | Система должна проводить пользователя через многошаговую анкету |
| БТ‑02 | Система должна валидировать параметры тела: вес, желаемый вес, рост, возраст |
| БТ‑03 | Система должна учитывать пол и признак грудного вскармливания |
| БТ‑04 | Система должна рассчитывать дневную норму КБЖУ |
| БТ‑05 | Система должна формировать план питания на 4 недели |
| БТ‑06 | Система должна учитывать пищевые ограничения, но не более 5 категорий |
| БТ‑07 | Система должна уточнять исключения по молочным, мясным и рыбным продуктам |
| БТ‑08 | Система должна формировать программу тренировок с учетом физических ограничений |
| БТ‑09 | Система должна учитывать место занятий |
| БТ‑10 | Система должна учитывать инвентарь для занятий дома, если не выбран вариант «без инвентаря»; |
| БТ‑11 | Система должна позволять выбрать проблемные зоны |
| БТ‑12 | Система должна предоставлять личный кабинет с данными участника |
| БТ‑13 | Система должна позволять сохранять вес не чаще 1 раза в день |
| БТ‑14 | Система должна позволять сохранять замеры не чаще 1 раза в день |
| БТ‑15 | Система должна строить график замеров, если замеров 2 и более |
| БТ‑16 | Система должна предоставить возможность ведения фото-прогресса(опционально) |
| БТ‑17 | Система должна показывать подобранный план питания, продукты, рецепт, правила, корзину на неделю, приемы пищи на неделю, КБЖУ, замену |
| БТ‑18 | Система должна показывать подобранную программу тренировок на неделю с видео |
| БТ‑19 | Система должна предоставлять ссылку на Telegram-чат с инструктором |
| БТ‑20 | Система должна позволять сбросить анкету и пройти ее заново |
| БТ‑21 | Система должна использовать заранее подготовленную базу приемов пищи, созданную нутрициологом |
| БТ‑22 | Система должна использовать заранее подготовленную базу тренировок, созданную тренером |

### Ограничения

- 12 недель
- 200 приемов пищи
- ограниченный ресурс
- без сложного design
- минимум кода (напишем только интерфейсы?)
- github projects: iteration project desk?

## Критерии приемки


| ID    | Критерий |
|-------|----------|
| КП‑01 | Пользователь проходит все шаги анкеты, ветвления работают |
| КП‑02 | Некорректные параметры тела и выбор блокируются |
| КП‑03 | Пол и грудное вскармливание учитываются в расчетах |
| КП‑04 | Суточная норма КБЖУ рассчитывается по формуле |
| КП‑05 | План питания на 4 недели составляется и отображается в личном кабинете |
| КП‑06 | Нельзя выбрать более 5 пищевых ограничений |
| КП‑07 | Исключение подкатегорий продуктов работают |
| КП‑08 | Программа тренировок составляется и отображается в личном кабинете |
| КП‑09 | Выбор "дом/зал" влияет на составление программы тренировок |
| КП‑10 | Для дома учитывается инвентарь (при выборе) |
| КП‑11 | Проблемные зоны сохраняются |
| КП‑12 | Данные участника отображаются в личном кабинете |
| КП‑13 | Вес сохраняется раз в день |
| КП‑14 | Замеры сохраняются раз в день |
| КП‑15 | График замеров строится от 2 записей |
| КП‑16 | Фото-прогресс доступен, но не обязателен |
| КП‑17 | На странице плана питания есть карточки приемов пищи, рекомендации и продуктовая корзина; карточка приема пищи содержит рецепт, ингредиенты, КБЖУ, кнопку замены |
| КП‑18 | Тренировки отображаются по неделям, видео воспроизводятся |
| КП‑19 | Ссылка на Telegram работает |
| КП‑20 | Анкету можно сбросить |
| КП‑21 | План питания строится только из приемов пищи, добавленных в базу |
| КП‑22 | Программа тренировок строится только из видео, добавленных в базу |
