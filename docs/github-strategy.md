# Стратегия ветвления

## Общее

Решено использовать Feature Branch стратегию:

- Ветка main защищена, пушить в нее запрещено
- Любая работа выполняется в отдельной короткоживущей ветке
- Любое изменение в main только через Pull Request
- История main должна быть линейной, используем Squash/Rebase
- Pull Request не может быть слит без успешных првоерок CI, проверок линтеров и одного одобрения

## Ветки

`main` - стабильная ветка, состояние прода

| Префикс  | Использование              | Пример                    |
|----------|----------------------------|---------------------------|
| feature/ | Новый функционал           | feature/auth              |
| fix/     | Исправление бага           | fix/auth-error            |
| hotfix/  | Срочное исправление бага   | hotfix/payment-error      |
| chore/   | Инфраструктура репозитория | chore/update-vite-scripts |
| docs/    | Документаия                | docs/github-strategy      |

Лучше именовать ветку с ID задачи, например: `<type>/<task-id>-<краткое-описание>`
